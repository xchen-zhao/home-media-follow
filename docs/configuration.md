# 配置与边界

实例配置位于 `<实例根目录>/config/shows.json`。初始配置由 `init` 生成，默认作品列表为空。配置格式版本为 `schema_version=1`，请求策略版本为 `policy_revision=3`。

## 实例目录与服务

| 配置 | 含义 |
|---|---|
| `cloud_root` | 本项目可写的网盘专用根目录；默认 `/HomeMediaFollow` |
| `openlist_mount` | 本机 OpenList 中该网盘的挂载点；默认 `/Baidu` |
| `media_root` | 归档父目录；Jellyfin使用其下 `动漫`、`电视剧`、`综艺` 分类目录作为电视剧库根 |
| `staging` / `recovery_root` | 在途文件和可恢复旧版；不能靠删除它们解除异常 |
| `publisher_lock` | 发布互斥锁，协调归档与换版 |
| `services` | OpenList、aria2、Jellyfin 的本机地址 |
| `ffprobe` | ffprobe 可执行文件路径；不设置时从 PATH 查找 |
| `min_free_bytes` | 排队和发布时保留的磁盘空间，默认10 GiB |

路径应使用绝对路径。自动计划任务安装器进一步要求媒体、暂存、恢复和发布锁路径位于实例根目录内，以限制授权范围；外部路径属于手动部署方式。服务地址必须包含端口、使用 HTTP，并且主机为 `127.0.0.1`、`localhost` 或 `::1`；不能夹带账号、查询串或片段。它们是本机控制入口，不应直接暴露到公网。

默认扫描时区为 `Asia/Shanghai`，`scan_interval_seconds=3600`，`recovery_interval_seconds=900`。Windows 任务触发器与程序门控必须配套；单独加快触发器不会突破配置里的扫描间隔。

## 来源登记

每部作品有稳定 `show_id`、正式 `title`、`media_kind`、`season`、`cloud_path` 和来源绑定。`media_kind` 当前为 `anime`、`tv` 或 `variety`。`cloud_path` 必须处于本实例的 `cloud_root` 内。

来源绑定至少包含分享短标识、该作品来源目录的稳定 ID 和完整路径。分享中混有多季时，以 `source_scope.allowed_parent_paths` 明确允许的本季相对目录；先过滤季与目录，再比较期号。不要把网盘目标目录名当作来源季数的证明。

可参考[单作品结构示例](../examples/show.example.json)。其中占位来源不是可用分享，必须替换为本机 `inspect-source` 核验得到的绑定，才能加入配置并激活。

默认 `catalog_mode=static`，仅扫描明确登记的分享及目录，不依赖私人笔记。`catalog_mode=yinxiang` 需要自行配置并核对该适配器；公开版本没有内置个人目录。

提取码和账号会话放在本机秘密存储中，配置只保存引用。配置验证会拒绝常见凭据字段。不要把“能通过 JSON 校验”当作来源身份、授权或画质已经核验。

## 订阅与下载范围

`activate_latest` 在完整扫描后记录订阅起点。首次取当时最新逻辑集；综艺取该期已发布的上下部分，同期后发下集仍可以加入。之后只处理起点范围内的新集和漏更，不把全部历史库存变成本地请求。

`pause` 暂停后续工作，`resume` 沿用原起点，`cancel` 取消后续追更。已提交的在途下载按既有授权收尾。恢复不能用重新激活或删除状态代替。

画质按实际分辨率档位决定；同档位不会因为名称、编码、HDR或码率不同而自动换版。未知高画质可暂用已验证的合格版本，后续仅在档位严格提高时升级。替换失败保留可观看旧版。

## 文件删除

当前支持用户在 Jellyfin 手动删除受管媒体，不自动按播放状态或新集入库清理旧集。媒体根可访问且受管已完成文件消失时，后台持久记录逻辑集不补回，覆盖同集全部画质版本。磁盘不可访问时保守停止补回，不误记为永久删除。

本地删集不代表云端删集。重新启动、暂停恢复或重新激活也不能绕过记录。当前没有精确 `restore` 命令；需要补回时先完善受控能力，不能手改状态解除门卫。

## 综艺显示序号

综艺的订阅起点、来源期数和上下逻辑身份保持原样。为避免 Jellyfin 将同一期上下合并为不同视频版本，内置发布器为每期保留三个显示序号：整期为 `3×期数−2`，上为 `3×期数−1`，下为 `3×期数`。例如第5期上、下的文件索引是 S04E14、S04E15，显示标题仍为“第5期上”“第5期下”。这是播放器排序用的索引，不代表节目已经更新到第14、15期。

首版不迁移已有家庭部署的文件或历史状态。
